# GEC6818 车载中控：编译、上板与测试清单

> 适用：`stage_project/`，主程序 `carmode`
> 当前配置：`audio=1`，歌曲 1/2/4 秒，14 张车机素材 + 5 张相册已替换并通过尺寸/格式检查

---

## 0. 上板前先确认

在 Ubuntu 编译机上：

```bash
arm-linux-gcc -v
```

如果没有，先把交叉工具链加入 PATH，或改用：

```bash
make CROSS_COMPILE=/opt/toolchain/bin/arm-linux-
```

开发板上确认：

```bash
ls /dev/fb0
ls /dev/input/event0
cat /sys/class/graphics/fb0/bits_per_pixel     # 应为 32
which madplay                                   # 要出声才需要
```

## 1. 编译

```bash
cd stage_project

# 方式一：CMake
sh build.sh
# 或
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=$PWD/cmake/arm-linux-toolchain.cmake
cmake --build build -j4

# 方式二：Makefile
make -j4
```

检查产物：

```bash
file build/bin/carmode      # CMake
file out/carmode            # Makefile
# 应包含 ARM, EABI5 等字样
```

## 2. 部署

开发板上建一个目录，例如 `/root/carmode`：

```
/root/carmode/
├── carmode
└── res/
    ├── car/
    ├── music/
    ├── photo/
    └── font/
```

**必须保持 `carmode` 和 `res/` 在同一级**，因为程序用相对路径读素材。

### 方式一：打包 + tftp

编译机上：

```bash
make pack
# 生成 out/carmode.tar.gz
```

开发板上：

```bash
tftp -g -r carmode.tar.gz 192.168.1.3
tar xzf carmode.tar.gz
cd .
./carmode
```

### 方式二：NFS

```bash
mount -t nfs -o nolock 192.168.1.3:/home/xxx/stage_project /mnt
cd /mnt
./build/bin/carmode
```

### 方式三：U 盘 / scp

把 `carmode` 和 `res` 一起复制到板子同一目录。

## 5. 音乐与音频测试

当前 `res/car/car.cfg`：

```ini
audio=1
song=夜空中最亮的星|逃跑计划|res/music/1.mp3|1
song=平凡之路|朴树|res/music/2.mp3|2
song=海阔天空|Beyond|res/music/3.mp3|4
```

当前文件实测：

| 文件 | 大小 | 时长 |
| --- | --- | --- |
| 1.mp3 | 13.8 KB | 约 0.86 秒 |
| 2.mp3 | 33.1 KB | 约 2.06 秒 |
| 3.mp3 | 64.0 KB | 约 4.0 秒 |

测试：

1. `which madplay` 有输出；
2. 进入音乐页，点播放，能听到声音；
3. 进度条按 1/2/4 秒走完并自动切下一首；
4. 暂停/继续正常；
5. 左右滑动切歌正常；
6. 音量 +/- 改变数字（音量对 madplay 的影响在下次开始播放时生效）。

### 没声音的排查顺序

1. `res/music/1.mp3` 等文件是否真的在板子上；
2. `res/car/car.cfg` 的 `song=` 路径是否和文件名一致；
3. `which madplay` 是否有输出；
4. `audio` 是否为 `1`；
5. 板子喇叭/耳机是否接好；
6. 如果只想做界面模拟，把 `audio` 改成 `0`，不需要 madplay。

## 6. 常见问题

**Q1：`open /dev/fb0` 失败**

```bash
ls /dev/fb*
cat /sys/class/graphics/fb0/bits_per_pixel
```

不是 32bpp 需要改 `lcd.c` 的像素格式。

**Q2：触摸没反应或坐标反**

```bash
ls /dev/input/
cat /proc/bus/input/devices
```

不是 `event0` 就改 `touch.c` 的设备路径；X/Y 反了交换映射。

**Q3：图标位置不对 / 盖住标题**

图标必须是 96×96；背景图 800×480；专辑 300×300；用
`tools/check_bmp.ps1 -Dir res/car -Any` 检查。

**Q4：运行提示 `GLIBC_2.xx not found`**

换板子配套的工具链，或：

```bash
make STATIC=1
```

**Q5：中文不显示**

确认 `res/font/simfang.ttf` 存在，并且是在包含 `res/` 的目录运行。

**Q6：程序一闪而过**

看终端日志；多半是运行目录不对（找不到 `res/car/car.cfg` 或字库），
或 `/dev/fb0` 权限不足。

## 7. 建议的验收演示流程

1. 上电，Logo + 进度条；
2. 主页介绍五个卡片和状态栏；
3. 进“导航”，说明模拟地图/路线，结束导航返回；

6. 进“相册”，点缩略图、左右切换、右上角关闭；
7. 进“电话”，选联系人、呼叫、挂断；
8. 进“设置”，切夜间主题，进倒车影像再返回；
9. 回主页，左右滑动展示页面切换；
10. 说明代码分层：驱动层 + 车载页面层 + CMake/Makefile。
